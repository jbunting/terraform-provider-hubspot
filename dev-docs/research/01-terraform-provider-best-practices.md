# Terraform Provider Engineering Best Practices (researched July 2026)

Sources: developer.hashicorp.com/terraform/plugin/*, hashicorp/terraform-provider-scaffolding-framework, release pages. This document sets the engineering conventions for this repo.

## 1. Framework choice

**Use `terraform-plugin-framework` — never SDKv2 — for this provider.** SDKv2 is maintenance-only. Framework advantages that matter here:

- Null vs unknown fidelity (`IsNull()` / `IsUnknown()`) — SDKv2 collapses both into Go zero values, causing drift bugs.
- Compile-time type safety (interface-based; typed request/response CRUD signatures).
- Plan modifiers (`RequiresReplace`, `UseStateForUnknown`), extensible validators, custom types (JSON semantic equality), ephemeral resources, resource identity.
- Datadog's ongoing SDKv2→framework mux migration shows the cost of starting on SDKv2.

## 2. Repo scaffold

Start from `hashicorp/terraform-provider-scaffolding-framework`:

```
terraform-provider-hubspot/
├── main.go                         # providerserver.Serve, version var via goreleaser ldflags, -debug flag
├── go.mod / go.sum
├── GNUmakefile                     # default, generate, testacc (TF_ACC=1 go test ./... -v -timeout 120m)
├── .goreleaser.yml                 # copy from scaffold verbatim
├── terraform-registry-manifest.json  # {"version":1,"metadata":{"protocol_versions":["6.0"]}}
├── .golangci.yml
├── internal/provider/              # provider shell; one file per resource: {name}_resource.go + _test.go
├── internal/client/                # hand-rolled HubSpot API client (zero raw HTTP in provider layer)
├── examples/
│   ├── provider/provider.tf
│   ├── resources/hubspot_{name}/resource.tf (+ import.sh)
│   └── data-sources/hubspot_{name}/data-source.tf
├── docs/                           # GENERATED by tfplugindocs — never hand-edit registry docs
├── templates/                      # optional .md.tmpl overrides
└── .github/workflows/test.yml, release.yml
```

Protocol **v6** (`providerserver.Serve` with `Address: "registry.terraform.io/{namespace}/hubspot"`). No muxing needed (greenfield).

## 3. Provider & resource architecture

- `New(version string) func() provider.Provider`; `Metadata` sets `resp.TypeName = "hubspot"`.
- Configure precedence: provider block attr > env var > error. Check `IsUnknown()` on config values (they may come from other resources' outputs). Build one API client; assign to `resp.ResourceData` and `resp.DataSourceData`.
- Each resource: struct with compile-time assertions (`var _ resource.Resource = &XResource{}`, `ResourceWithImportState`), mandatory nil-check in `Configure` (ValidateResourceConfig RPC runs before ConfigureProvider).
- One typed model struct per resource using framework `types` (`types.String`, etc. — never raw Go types) with `tfsdk` tags.
- Prefer nested **attributes** (`SingleNestedAttribute`, `ListNestedAttribute`) over legacy blocks.
- Plan modifiers: `UseStateForUnknown()` on computed-once attributes (`id`), `RequiresReplace()` on immutable API fields; resource-level `ModifyPlan` for cross-attribute logic (create = `req.State.Raw.IsNull()`, destroy = `req.Plan.Raw.IsNull()`).
- Validators from `terraform-plugin-framework-validators` (`stringvalidator.OneOf`, `RegexMatches`, `ConflictsWith`, …). Custom validators must return early on null/unknown.
- Defaults (`stringdefault.StaticString`) only on Optional+Computed; don't invent defaults diverging from the API's own.

## 4. CRUD/state semantics

- **Create/Update:** set every attribute (incl. computed) and `resp.State.Set` — even on partial failure after a successful API mutation, persist state first, then return error diagnostics. Otherwise resources leak/orphan.
- **Read** is the drift-detection workhorse: refresh **all** attributes, not a subset. Remote 404 → `resp.State.RemoveResource(ctx); return`. Preserve semantically-equal prior values (use custom types like `jsontypes.Normalized` for JSON attributes).
- **Delete:** return nothing on success (framework removes state); treat "already gone" 404 as success.
- **ImportState:** every resource must be importable. Single ID → `ImportStatePassthroughID`; composite natural keys (`objectType/name`) → parse `req.ID`, validate format with helpful error, `SetAttribute` per part.
- State never contains unknowns; planned values must match applied state or Terraform errors.
- Timeouts opt-in via `terraform-plugin-framework-timeouts`.

## 5. Testing

- Acceptance tests with `terraform-plugin-testing` v1.16 (not SDKv2 helper/resource), gated by `TF_ACC=1`, run against a dedicated test portal; resource names prefixed `tf-acc-test`.
- Canonical TestCase: ProtoV6ProviderFactories + steps: create/read (with `statecheck.ExpectKnownValue`), import round-trip (`ImportState: true, ImportStateVerify: true`), update, implicit destroy + `CheckDestroy`.
- Prefer modern `plancheck`/`statecheck`/`knownvalue` packages over `TestCheckResourceAttr` string checks. Use `plancheck.ExpectResourceAction(..., ResourceActionReplace)` to test RequiresReplace behavior.
- Sweepers (`resource.AddTestSweepers` + `go test -sweep=all` make target) to clean leaked test infra.
- Unit tests: pure logic (model↔API conversion, ID parsing) table-driven; hermetic runs by pointing the client's configurable base URL at `httptest.NewServer` (this is why `api_base_url` must exist). `go-vcr` cassettes are an option for CI with real-portal nightly runs as source of truth.
- CI (3 jobs): build+golangci-lint; generate (tfplugindocs, fail on `git diff --exit-code`); TF_ACC matrix across supported Terraform versions with `terraform_wrapper: false`. Pin actions by SHA.

## 6. Release & publishing

- Repo name `terraform-provider-hubspot` (lowercase), semver tags `vX.Y.Z`.
- GoReleaser produces: per-platform zips, `_SHA256SUMS`, binary (not ASCII-armored) GPG `.sig`, `_manifest.json` (protocol 6.0). Binary built with `-ldflags "-X main.version={{.Version}}"`.
- GPG: RSA/DSA key (not ECC); public key registered in Registry settings; private key + passphrase in GH Actions secrets.
- Docs generated by tfplugindocs from live schema + `examples/` + `templates/`; `MarkdownDescription` on every attribute is the source of truth; `tfplugindocs validate` in CI. Never mutate a released tag.

### OpenTofu Registry (dual publishing — required for this project)

OpenTofu speaks the same plugin protocol (v5/v6), so the same binary and the same GitHub release artifacts serve both ecosystems — no separate build or release pipeline.

- **Publishing**: the OpenTofu Registry (registry.opentofu.org) indexes providers from GitHub releases of `terraform-provider-*` repos. Submit the provider once via the [opentofu/registry](https://github.com/opentofu/registry) repo (issue/PR adding the provider's metadata JSON), and separately submit the **GPG signing public key** so releases verify as signed. After inclusion, new tags are picked up automatically from GitHub releases — keep the standard goreleaser asset set (zips, SHA256SUMS, .sig, manifest) and both registries stay in sync.
- **Compatibility rules**: don't depend on Terraform-CLI-only features or version checks; treat `required_version` guidance and docs as tool-neutral ("Terraform or OpenTofu"). Users reference the provider as `hubspot/...` from whichever registry their tool defaults to; example `required_providers` blocks work unchanged.
- **CI**: run the acceptance matrix against OpenTofu releases in addition to Terraform (`terraform-plugin-testing` honors `TF_ACC_TERRAFORM_PATH` pointing at a `tofu` binary; `hashicorp/setup-terraform` has an OpenTofu counterpart `opentofu/setup-opentofu`). A provider that only ever ran under Terraform CI can silently regress for OpenTofu users.
- jackemcpherson/hubspot already dual-publishes (terraform.io + opentofu.org identities) — precedent in this exact niche.

## 7. API client design

- Separate `internal/client/` package; resources call typed methods (`client.Pipelines.Create(ctx, req)`), zero raw HTTP in provider layer.
- Constructor takes: base URL (configurable → httptest mocking), token, custom `*http.Client`, User-Agent with provider name/version.
- Every method takes `ctx` first and uses `http.NewRequestWithContext` (Terraform cancels on Ctrl-C).
- Retry/backoff in the client layer (`hashicorp/go-retryablehttp` pattern): 429 + 5xx with exponential backoff + jitter; honor `Retry-After` when present. Proactive `golang.org/x/time/rate` limiter (HubSpot has hard 10-second-window limits and Terraform defaults to parallelism 10).
- Pagination: client exposes `ListAll` helpers following `paging.next.after`; never leak paging tokens into schemas.
- Client returns typed Go errors (`ErrNotFound` / `IsNotFound(err)`); only the resource layer converts to `resp.Diagnostics.AddError`. Wire logging via `tflog.Debug/Trace` — never stdout (corrupts go-plugin protocol).

## 8. Design principles (HashiCorp) & versioning

1. One provider = one API/problem domain.
2. **One resource = one API object**; no client-side composites (those belong in Terraform modules).
3. Schema mirrors the upstream API (names, structure); RFC 3339 timestamps; booleans phrased so `true` = enabled.
4. Every resource importable.
5. State continuity within a major version; `StateUpgrader` + `schema.Version` on shape changes.
6. Provider functions must be pure/offline; network-dependent → data source.
7. Ephemeral resources for short-lived secrets.

Versioning: strict semver. MAJOR = removals/renames/ID-format/auth-precedence/type changes. MINOR = features and new deprecations (`DeprecationMessage` first, remove next MAJOR). PATCH = fixes only. `CHANGELOG.md` categories: BREAKING CHANGES, NOTES, FEATURES, ENHANCEMENTS, BUG FIXES.

Reference implementations: scaffolding-framework template, HashiCups tutorial, cloudflare (v5, framework-native), grafana, integrations/github (mux example).
